## 一、先说缺失与冲突（按要求先声明）

### 1. 示例源码不可读（主要缺失）
`xiaomei.zip` 里**只有打包产物**，没有源码：

| 内容 | 说明 |
|---|---|
| `xiaomei.exe`（13 MB） | 应用的全部 Python 代码是编译进 exe 的字节码（PyInstaller PYZ），**无法直接读出** |
| `_internal/`（约 3200 项） | 几乎全是 PySide6/Qt 运行库与第三方依赖（aiohttp、botocore 等），不是示例自身代码 |
| `_internal/app/ui/resources/` | 仅 4 个文件：`pet.png`（示例角色立绘）、`pet.ico`、`style_dark.qss`、`style_light.qss` |

也就是说：示例的**动画曲线、事件处理、状态机、菜单逻辑都拿不到原文**，只能从其资源（一张立绘 + 两份 QSS 样式表）和桌面宠物的通行做法推断。

### 2. 框架冲突（不能直接照搬）
示例是 **PySide6/Qt**（原生窗口 + QSS 样式），桌宠是 **pywebview + HTML/CSS/JS**。
Qt 的 QWidget/QMenu/QSS **无法直接搬进**桌宠，所以做法是：**复刻其交互能力与体验，用桌宠原有的 HTML/CSS/JS 重新实现**，而不是替换技术栈。

### 3. 角色形象不能用
示例的 `pet.png` 是它自己的角色（小美）。按要求「保留小狗原有美术风格」，**没有采用示例立绘**，界面配色沿用桌宠现有的暖色（#f7dbcf / #ff8f9a / #5d4038 一类）。

> 结论：缺失的是"示例源码"，冲突的是"Qt vs Web 技术栈"。下面按可推断的部分在**不破坏原有功能**的前提下完成复刻，体验对等或更好（页内菜单比系统菜单更可控、更好看）。

## 二、本次升级的功能（对应示例能力）

### 1. 动画与过渡效果
- 悬停：立绘轻微上浮（`translateY(-4px)`），带弹性曲线（cubic-bezier）。
- 按下：下沉并微缩（`.press`），松手回弹。
- 状态过渡：按 `data-state` 切换呼吸/摇摆动画的节奏与明暗（困倦放慢变暗、开心加快提亮），全部走 CSS transition，不生硬跳变。
- 说话时自动进入 `talking` 状态，说完回到上一个状态（困了继续困）。

### 2. 鼠标交互
- **悬停**：出现提示气泡，文案按她的性格来（「咋，想摸我？」「再摸就收费了昂」「包行的，摸吧」…随机）。
- **单击**：原有 `poke()`（戳一下）保持不变。
- **双击**：打开聊天（原有行为，未改）。
- **右键**：弹出**页内菜单**（新增）。
- 拖拽窗口：原有拖区保留；菜单打开时临时摘掉拖区，避免"点菜单变成拖窗口"。

### 3. 键盘交互（新增）
| 键 | 作用 |
|---|---|
| 空格 | 摸一下（等同单击） |
| Enter / S | 打开聊天 |
| M | 语音开 / 关 |
| H | 心情变好（脸红 + 冒爱心） |
| Z | 睡一会 / 起床 |
| L | 四处看看 |
| Esc | 关闭菜单 |

### 4. 状态与行为切换
新增轻量状态机 `setState()`：`idle / happy / sleepy / talking / menu`。
只改**表现层**（动画节奏、明暗、提示），动作全部复用原有的 `poke / openChat / say / lookAround / setBlush / spawnHearts`，**不改动原有行为逻辑**。
`startTalking / stopTalking` 已接入状态机，状态与真实行为同步。

### 5. 提示气泡与菜单
- **悬停提示气泡**（`#tip`）：暖色圆角、淡入淡出。
- **页内右键菜单**（`#menu`）：摸摸头 / 说句话 / 睡一会·起床 / 置顶 / 语音 / 打开聊天 / 更多（系统菜单）/ 退出。
  - 每个动作优先调 pywebview 接口，调不到就**明确提示**（不静默失败）；
  - 「更多（系统菜单）」保留原来的 `show_menu()`，原功能一点没丢。
- **状态提示 toast**（`#toast`）：切换状态时给一句短提示。
