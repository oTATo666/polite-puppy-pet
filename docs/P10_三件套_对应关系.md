# P10 三件套 · 对应关系与使用说明

配套文件：

| 文件 | 层次 | 回答的问题 | 谁在用 | 什么时候用 |
|---|---|---|---|---|
| `今晚任务清单_20261027.md` | **计划层** | 今晚要做哪些事、做到什么算完 | 执行人 | 开工前定，中途对照 |
| `任务报表_P10_20261027.md` / `.csv` | **执行层** | 每件事现在到哪一步、卡在哪 | 执行人填，审查人核 | 每完成一项就改，收工汇总 |
| `明早审查安排_20261028.md` | **验收层** | 怎么证明真做成了、能不能放行 | 审查人 / 决策人 | 明早 08:45–10:30 |

---

## 1. 三者的关系：同一条标准的三种时态

```
清单的「完成标准」  ──将来时──▶  报表的「完成证据」  ──完成时──▶  审查的「通过阈值」 ──判定──▶ 放行/退回
      （怎么算完）                    （凭什么说完了）                （别人怎么复核）
```

一句话：**清单写标准，报表交证据，审查按同一标准复核**。三段必须能对上，否则就是自说自话。

举例（T6）：

- 清单：完成标准 = 「脚本退出码 0，输出『通过 N 项，未过 0 项　总判定：PASS』」
- 报表：完成证据 = 「`python tools\verify_p10.py` → 通过 31 项，未过 0 项」
- 审查：R3 通过阈值 = 「『未过 0 项』，退出码 0」+ R4 顺带核 12 例路由

三处用的是同一句话，所以审查人不需要重新定义"什么叫通过"。

---

## 2. 编号是贯穿的（三处必须同号）

- **T 号**：清单里定义，报表里一行一条，**不复用、不跳号**。基线项（开工前已完成的）记为 `T0-x`。
- **R 号**：审查里定义，每条 R 至少挂一个 T。
- **不新增第四个编号体系**：问题记录用 `Q1/Q2`，只挂在 R/T 上，不单独成表。

## 4. 一致性规则（不遵守就会自相矛盾）

1. **改清单必改两处**：清单里增删一个 T，报表要加/删同一行，审查要有对应 R（或明确写"不审"）。
2. **报表不许出现清单里没有的 T**。临时加做的事，先补进清单再填报表。
3. **审查不许引入新的验收标准**。R 的阈值只能来自清单的「完成标准」原话；要加严，得先回改清单并说明原因。
4. **状态与结论必须同口径**：报表的收工判定 A/B/C 与审查的三档结论一一对应——
   - 报表 A 可交付 → 审查走全流程 → 期望「放行」
   - 报表 B 部分交付 → 审查只做代码与接口 → 期望「条件放行」
   - 报表 C 已阻塞 → 审查按退回分支复盘 → 不带病上线

## 5. 时间轴（三件套怎么串起来）

```
今晚 21:15   看清单开工
今晚 每完成一项  → 报表立刻改该行（状态+证据）
今晚 23:25   中场对表（前 5 行是否全绿）
今晚 00:30   熔断检查点（T6 未 PASS 就回滚并记「已阻塞」）
今晚 01:30   报表收工汇总 + 填判定 A/B/C
明早 08:45   审查人拿同一份报表抽 3 行核证据
明早 09:00   跑自动批（R2/R3/R4/R8/R11）
明早 09:25   真机手动走查（R5/R6/R7/R9）
明早 10:15   结论会 → 放行 / 条件放行 / 退回
```

## 6. 现在就能用的一句话版本

> 今晚按 T1→T11 做，做一项在报表里改一行并贴证据；明早审查人打开报表抽 3 行，然后照 R1→R13 跑一遍，10:30 出结论。清单、报表、审查用的是同一套 T 号和同一句完成标准，任何一处改动都要三处同步。
