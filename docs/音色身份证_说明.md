# 小狗「音色身份证」——持久化声线 ID · 音色保全 · 实时同步

## 一句话

给小狗的克隆声线办一张**身份证**：一个持久不变、且与参考音频指纹绑定的 `voice_id`。
以后不管谁在合成，都先亮身份证再出声，确保**出来的永远是"小狗自己那条声线"**。

当前身份证：

| 项 | 值 |
|---|---|
| voice_id | `puppy_小狗_e82c45be` |
| owner | 她 |
| 档案 | 小狗（`voices/profiles/小狗/`） |
| 参考音频 | `voices/profiles/小狗/ref.wav`（347,394 字节） |
| 音色指纹 | sha256 `e82c45be…dcb007` |
| 锁定参数 | speed 1.45 / seed 20261025 / nfe 12 |

文件落在 `voices/voice_id.json`。

---

## 解决了哪三个隐患

### 1. 音色漂移：ID 和声音没绑定
原来"音色 ID"只是档案目录名（如「小狗」），跟真正的参考音频没关系。
**参考音频被换掉，ID 还叫「小狗」，谁也发现不了。**

现在：`voice_id` 与参考音频的 sha256 指纹绑定。换参考音会被 `verify()` 判定为
**漂移（drift）** 并留痕到 `history`，但 `voice_id` 保持不变——这样你仍能认出"还是这只狗"。

### 2. 静默换声：悄悄用了别人的录音
`f5_clone.py` 里原来有个 `REF_FALLBACK`，指向**另一个目录下的参考音频**；
一旦档案里的 ref 读不到，就会悄悄用那个路径去合成——**声音变成别人，且毫无提示**。

现在：参考音频一律经身份证解析（`resolve()`）；解析不到就**直接报错**，
绝不悄悄回落。宁可不出声，也不出别人的声。

### 3. 各组件不同步
现在所有出声路径（F5 服务、主程序）都在"要出声的那一刻"向身份证取当前声线，
并且**同时盯住三个文件**的修改时间：`voice_id.json`、`voices/active.json`、
当前档案的 `profile.json`。任一变动立即重载——**切换音色不用重启服务**。

## 怎么用

### 命令行
```bat
python tools\voice_identity.py show      :: 看当前声线身份证
python tools\voice_identity.py verify    :: 校验音色有没有漂移
python tools\voice_identity.py init      :: 换了参考音源后重建
```

`verify` 正常输出：
```
"voice_id": "puppy_小狗_e82c45be",
"drift": false,
"message": "音色一致 ✅"
```

### 接口（实时同步用）
- F5 服务：`GET http://127.0.0.1:9880/voice`
- 主程序：`GET /api/voice/id`

都返回 `voice_id / owner / ref / params / drift / message`，界面或脚本可随时确认
"现在是不是小狗自己的声线"。

### 代码里取声线
```python
from voice_identity import resolve
v = resolve()            # {voice_id, ref_audio, ref_text, speed, seed, nfe, profile_id}
```

## 关键设计取舍

- **ID 持久优先**：参考音频换了也保留原 `voice_id`，靠 `drift` 与 `history` 暴露变更，
  而不是生成新 ID——否则"小狗的声线"这个身份会随每次换音源而丢失。
- **绝不静默回落**：拿不到身份证就抛错。音色错误比没有声音更糟糕。
- **实时但不轮询**：用文件 mtime 做缓存键，零额外开销，改动即刻生效。
