# 修复：语音输出回退到系统默认音色

> 修复时间：2026-10-29 01:05

## 一、根因（三条，互相叠加）

### 1. 克隆分支被默认配置挡死（主因）
`SpeechEngine.clone_allows()` 原来的闸门是：

```python
if self.clone_always:  return n <= 120
return self.clone_max > 0 and n <= self.clone_max    # VOICE_CLONE_MAX_CHARS 默认 0
```

`VOICE_CLONE_MAX_CHARS=0`、`VOICE_CLONE_ALWAYS` 未开时 → **克隆分支永远进不去**。

### 2. 禁用系统音的闸门形同虚设
```python
allow_sapi = self.sapi_enabled and not (self.clone_always and self.clone.ready())
```
只有 `clone_always` **且**克隆就绪时才关系统音。`clone_always=False` → 闸门恒开 → **每句都掉进 SAPI 系统合成音**。即便克隆失败，也只是 `log.debug` 一行，然后照样用系统音——典型的"静默回退"。

### 3. 运行目录下缺 `.env`（很可能就是你这次遇到的）
`VOICE_TTS_URL / VOICE_TTS_VOICE / VOICE_ALLOW_SYSTEM` 都在 `.env` 里。若 exe 旁边没有 `.env`：

- `VOICE_TTS_URL` 为空 → `CloneTTS.ready()` 为 False → 克隆不可用
- `VOICE_ALLOW_SYSTEM` 未设置 → 默认 **True** → 系统音开启

**桌面最新版包的 `01_程序\` 之前就没带 `.env`**，从那里跑 exe 必然出系统音（现已补上）。

## 二、修复内容

| # | 改动 | 作用 |
|---|---|---|
| 1 | `SpeechEngine.__init__` 开头主动 `load_dotenv(exe_dir()/".env")` | 无论引擎何时被构造，配置一定已加载，杜绝"读不到 .env" |
| 2 | 新增 `VOICE_STRICT_CLONE`（**默认开**）与 `_verify_clone()` | 启动即校验：地址 → 服务健康 → 音色身份证，任一步失败记明确原因 |
| 3 | `clone_allows()` 严格模式下只要克隆可用就返回 True | 不再被 `MAX_CHARS=0` 卡死 |
| 4 | 播报链路：克隆不可用/失败 → 返回 `silent` + `reason` + `message` | **明确报错、保持安静，绝不静默换系统音** |
| 5 | `allow_sapi` 增加 `and not self.strict_clone` | 严格模式下系统音分支永久关闭；真走了会 `log.warning` |
| 6 | `CloneTTS._payload()` 固定带 `model`+`voice`，未配置时向音色身份证取档案名 | 实时流式全链路固定指定小狗音色，不用服务端默认音色 |
| 7 | 关键日志：每次请求打印 `url/model/voice`，启动打印 `voice_id/model/ref/drift` | 随时能确认"实际用的是哪个音色和模型" |
| 8 | `/api/voice/diag` 增加 `VOICE_*` 开关与 `clone_voice`（voice_id/ref/params/drift） | 一眼查当前音色状态 |
| 9 | 桌面最新版包补入 `.env` | 否则那里跑 exe 必然回退系统音 |

## 三、验证结果（实测，非推断）

```
strict_clone       = True          ← 严格克隆已开
sapi_enabled       = False         ← 系统音已关
clone.url          = http://127.0.0.1:9880/v1/audio/speech
clone.voice/model  = 小狗 / f5
clone.ready()      = True
_verify_clone()    → ok=true，server={engine:f5-tts, device:cuda, ready:true}
                     voice_id=puppy_小狗_e82c45be  ref=voices/profiles/小狗/ref.wav  drift=false
clone_allows()     → 2字 True / 7字 True / 149字 False（120 字上限内正常）
allow_sapi         = False         ← 系统音闸门已关闭
```

## 四、怎么确认"现在确实是克隆音色"

1. 启动日志里应有：`克隆音色就绪：voice_id=puppy_小狗_e82c45be model=f5 voice=小狗 ref=... drift=False`
2. 若克隆不可用，日志会明确写：`克隆音色不可用：<原因>（严格克隆=True，已禁止回退系统音）`
3. 浏览器打开 `http://127.0.0.1:<端口>/api/voice/diag`，看 `clone_voice.voice_id` 与 `flags.VOICE_TTS_URL`
4. 每次出声都有：`播报引擎=clone model=f5 voice=小狗 文本="..."`

## 五、注意

- 严格克隆下，克隆服务挂掉时小狗会**不出声**（而不是用系统音顶替）。这是刻意的：宁可安静，也不放一个音色对不上的声音。想临时放开就设 `VOICE_STRICT_CLONE=0`。
- 低延迟未受影响：整句缓存命中仍 0ms，克隆合成走的是原来的异步线程与缓存机制。
